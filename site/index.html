How it is verified

rive-cli compare decompiles both files, renders both through headless Chromium at identical geometry, and reports two things: a table of every Rive type whose count differs, and the share of pixels that differ per frame. It exits non-zero only when you give it a threshold to fail against, so the number is the deliverable rather than a hidden pass mark. The tool also measures a single file on its own — distinct colours, dominant-colour ratio, content bounding box and an ASCII coverage map — because an agent cannot look at a picture. The site validation loads every official and reproduction canvas, asserts that each one paints, and checks that the displayed object counts and pixel figures match the committed parity/results.json. That results file is regenerated by parity/collate-results.sh, which runs the same thresholded comparison for each shipped rung. The existing visual regression baselines cover related committed fixtures, not these parity cards. Fetched official files are checksum-verified against upstream commits; legacy in-repo files are checksum-verified locally.

Quickstart

$ cargo install --path .
$ rive-cli new spinner > scene.json
$ rive-cli generate scene.json -o scene.riv
$ rive-cli validate scene.riv
$ rive-cli compare official.riv ours.riv --frames 0,15,30 --max-pixel-diff 5

rive-cli describe <type> reports the fields, valid parents and animatable properties of any of the ~200 object types, and rive-cli schema emits the full JSON Schema for a scene.
